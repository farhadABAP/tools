☁️ ABAP Cloud

Three Important Development Models

Model Typical Usage Important Point
Standard ABAP Classic / traditional systems Broad language and repository access
ABAP for Cloud Development BTP ABAP environment / S/4HANA Cloud Restricted language + released APIs
ABAP for Key Users Key-user extensibility More restricted development model

ABAP Cloud Principles

  • Cloud-compatible language version
  • Released SAP APIs
  • Stable extension points
  • ADT as development environment
  • Clean Core
  • Upgrade-stable extensions
Exam trap: Do not assume that every classic ABAP statement or direct database access is available in ABAP for Cloud Development. Always ask: "Is this API / statement / object released and allowed in the target development model?"

⌨️ Modern ABAP

Inline Declaration



DATA(lv_name) = |Farhad|.

LOOP AT lt_customers INTO DATA(ls_customer).

    DATA(lv_text) =
        |Customer: { ls_customer-name }|.

ENDLOOP.

VALUE Operator



DATA(lt_numbers) =
    VALUE int4_table(
        ( 10 )
        ( 20 )
        ( 30 )
    ).

Table Expression



DATA(ls_customer) =
    lt_customers[ id = 100 ].

String Template



DATA(lv_text) =
    |Customer { lv_id } has status { lv_status }.|.
Know the concept: Be able to recognize modern syntax in existing code, not only write it from memory.

Modern SELECT



SELECT FROM zcustomer
       FIELDS id,
              name,
              status
       WHERE status = @lv_status
       INTO TABLE @DATA(lt_customers).

Code Pushdown

Code pushdown means moving data-intensive processing as close to the database as appropriate instead of retrieving large datasets and processing everything in ABAP.

Remember: Avoid unnecessary database round trips and unnecessary data transfer. Prefer appropriate SQL/CDS-based processing where possible.

📊 CDS Data Modeling

CDS View Entity



@EndUserText.label: 'Customer'

define view entity ZI_Customer
    as select from zcustomer
{
    key id,
        name,
        status,
        created_by
}

Association



define view entity ZI_Customer
    as select from zcustomer

    association [0..1]
        to I_CompanyCode as _CompanyCode
        on $projection.CompanyCode =
           _CompanyCode.CompanyCode
{
    key id,
        CompanyCode,
        _CompanyCode
}

Path Expression



_CompanyCode.CompanyName as CompanyName
Know: Understand the difference between associations, joins, cardinalities and path expressions.

⚙️ RAP Behavior Definition

Managed Behavior



managed implementation in class
    zbp_i_customer unique;

strict ( 2 );

define behavior for ZI_Customer
persistent table zcustomer
lock master
authorization master
{
    create;
    update;
    delete;

    field ( readonly ) id;

    determination setStatus
        on modify { create; }

    validation checkName
        on save { create; update; }

    action approve result [1] $self;
}

Determination

Automatically derives or changes values based on business events.

Validation

Checks whether business data is valid before saving.

Action

Represents an explicit business operation initiated by a consumer or application.

Very important: Do not confuse determination, validation and action.

⚡ Entity Manipulation Language

CREATE



MODIFY ENTITIES OF ZI_Customer
    IN LOCAL MODE

    ENTITY Customer

    CREATE FIELDS
        ( name status )

    WITH VALUE #(
        (
            %cid   = 'C1'
            name   = 'Test'
            status = 'NEW'
        )
    )

    MAPPED DATA(lt_mapped)
    FAILED DATA(lt_failed)
    REPORTED DATA(lt_reported).

READ



READ ENTITIES OF ZI_Customer
    IN LOCAL MODE

    ENTITY Customer
    ALL FIELDS WITH VALUE #(
        (
            id = 100
        )
    )

    RESULT DATA(lt_result)
    FAILED DATA(lt_failed)
    REPORTED DATA(lt_reported).

🌐 Service Definition / Binding / OData

Service Definition



@EndUserText.label: 'Customer Service'

define service ZUI_CUSTOMER {

    expose ZI_Customer
        as Customer;

}

Service Binding

The service binding connects the service definition to a protocol and runtime used to expose the service.

Know the Difference

Artifact Question to Ask
CDS What is the data model?
Behavior What operations/business rules exist?
Service Definition What should be exposed?
Service Binding How is the service exposed?
Common confusion: Service definition and service binding are not the same artifact.

🧹 Clean Core & Extensibility

Why Clean Core?

The Clean Core approach aims to keep the SAP core stable and upgradeable while placing extensions in appropriate supported extension mechanisms.

Important Concepts

  • In-app extensibility
  • Developer extensibility
  • Side-by-side extensibility
  • Released APIs
  • Extension points
  • Upgrade stability
  • ABAP Cloud
Exam thinking: When several extension approaches are possible, consider whether the solution follows supported extension mechanisms and Clean Core principles.

⚠️ C_ABAPD Exam Traps

Trap 1 — Classic ABAP ≠ ABAP Cloud

A statement or API that works in traditional ABAP does not automatically mean it is allowed in ABAP for Cloud Development.

Trap 2 — CDS ≠ RAP

CDS is used for data modeling and more. RAP builds transactional behavior and services around business objects.

Trap 3 — Determination ≠ Validation

A determination derives or changes values. A validation checks business consistency.

Trap 4 — Service Definition ≠ Service Binding

The definition describes what is exposed. The binding connects the service to its runtime/protocol.

Trap 5 — Association ≠ Join

Know why and when associations are used and how cardinality and path expressions work.

Trap 6 — Managed ≠ Unmanaged

Understand which parts of persistence and transactional processing are handled by the RAP framework and which parts require developer implementation.

Trap 7 — EML ≠ ABAP SQL

ABAP SQL works with database data. EML interacts with RAP business objects.

Trap 8 — Memorization Only

Do not prepare by memorizing code blocks. Be able to read a scenario and select the appropriate artifact or mechanism.

❓ Practice Questions

1. Which technology is primarily used for defining a modern ABAP Cloud data model?

A. Dynpro
B. CDS
C. Smart Forms
D. SAPscript

Answer: B — CDS

2. What is the main purpose of a RAP Behavior Definition?

A. Define database indexes
B. Define transactional behavior
C. Define CSS
D. Define an SAP GUI screen

Answer: B — Define transactional behavior

3. What is EML primarily used for?

A. Manipulating RAP business objects
B. Styling Fiori applications
C. Creating database indexes
D. Managing operating-system files

Answer: A — Manipulating RAP business objects

4. Which artifact is used to define authorization restrictions for CDS data access?

A. DCL
B. BDEF
C. Service Binding
D. Behavior Pool

Answer: A — DCL

5. Which concept is strongly associated with ABAP Cloud?

A. Unlimited direct access to every SAP object
B. Released APIs and supported extension points
C. Mandatory Dynpro development
D. SAPscript-only development

Answer: B

6. What is the purpose of a determination?

A. Automatically derive or modify values
B. Define authorization roles
C. Expose an OData service
D. Create a database table

Answer: A

7. What is code pushdown?

A. Moving suitable data processing toward the database
B. Moving all logic into the UI
C. Moving ABAP code into JavaScript
D. Removing CDS

Answer: A

8. Which sequence best describes a typical RAP service?

A. CDS → Behavior → Service Definition → Service Binding
B. Dynpro → Smart Form → JavaScript
C. SQL → SAPscript → GUI status
D. DCL → Dynpro → BAdI

Answer: A
