🎯 Exam Format & Strategy

System-Based Practical Exam: You will write actual ABAP code in an SAP BTP ABAP Environment (Steampunk) system using Eclipse ADT or SAP Business Application Studio (BAS).

  • Open-Book: You can use SAP Help and your own resources. Focus on knowing what to search for, not memorizing syntax.
  • Joule Integration: The exam explicitly tests your ability to use SAP's AI assistant, Joule, to accelerate development.
  • ABAP Cloud Restrictions: Classic ABAP (like COMMIT WORK or direct SELECT from standard tables) is forbidden. You must use released APIs and CDS views.
  • Time Management: 3 hours is tight. Use Joule to generate boilerplate, and focus your time on business logic and troubleshooting.

⏱️ Your 3-Year Experience Advantage

With 3 years of ABAP experience, you already understand core concepts. Your challenge is unlearning classic ABAP habits and building muscle memory for ABAP Cloud syntax. Expect 3-4 weeks of focused study (1.5-2 hours/day).

Module 1: ABAP Cloud Fundamentals STEAMPUNK

What is ABAP Cloud?

ABAP Cloud (formerly Steampunk) is the development model for the SAP BTP ABAP Environment. It enforces a strict subset of ABAP to ensure cloud compatibility, multi-tenancy, and upgrade stability.

🚫 Key Restrictions (Exam Favorites)

  • No Direct DB Access: You cannot use SELECT * FROM mara. You must read data via CDS View Entities or released APIs.
  • No Classic Commits: COMMIT WORK is forbidden. Use COMMIT ENTITIES or let the RAP framework handle it.
  • No Classic UI: WRITE, ALV, and SELECTION-SCREEN are not allowed. UI is handled by Fiori Elements.
  • Whitelists: Only "released" SAP objects (classes, interfaces, CDS views) can be used. Check the "Released Objects" app in BAS.

✅ Modern ABAP Syntax (Clean ABAP)

" Inline declarations (Mandatory in Cloud)
DATA(lv_count) = 0.
DATA(ls_struct) = VALUE zstruc( ).

" Modern loops
LOOP AT lt_data INTO DATA(ls_item).
  " ...
ENDLOOP.

" String templates
DATA(lv_text) = |Hello { sy-uname }, today is { sy-datum DATE = ISO }|.

Module 2: ABAP Object-Oriented CLEAN CODE

Executable Classes (Class Run)

In ABAP Cloud, you test your code using executable classes that implement IF_OO_ADT_CLASSRUN. This replaces the old REPORT and START-OF-SELECTION.

CLASS zcl_my_test IMPLEMENTATION.
  METHOD if_oo_adt_classrun~main.
    out->write( 'Hello ABAP Cloud!' ).
    
    " Call your business logic
    DATA(lo_proc) = NEW zcl_processor( ).
    lo_proc->run( ).
  ENDMETHOD.
ENDCLASS.

Exception Handling

Forget SY-SUBRC. ABAP Cloud uses class-based exceptions. You must catch them or declare them in the method signature.

METHOD process_data.
  TRY.
      DATA(lv_result) = calculate( iv_input ).
    CATCH cx_root INTO DATA(lx_error).
      " Log or re-raise
      RAISE EXCEPTION TYPE zcx_custom_error
        EXPORTING
          previous = lx_error.
  ENDTRY.
ENDMETHOD.

Module 3: CDS View Engineering FOUNDATION

Why CDS in ABAP Cloud?

CDS (Core Data Services) is the virtual data model. In ABAP Cloud, it's the only way to access standard SAP database tables. It also drives the Fiori UI via annotations.

Essential Annotations for Fiori

@EndUserText.label: 'Billing Document'
@Search.searchable: true
define root view entity ZI_BillingDoc
  as select from I_BillingDocument
{
      @UI.hidden: true
  key BillingDocument,
      
      @UI.lineItem: [{ position: 10, label: 'Customer' }]
      @Search.defaultSearchElement: true
      CustomerName,
      
      @UI.lineItem: [{ position: 20, label: 'Net Amount' }]
      TotalNetAmount,
      
      @UI.lineItem: [{ position: 30, label: 'Currency' }]
      TransactionCurrency
}

Associations & Path Expressions

Use associations to navigate between entities without writing complex JOINs.

association [0..1] to I_CompanyCode as _CompanyCode 
  on $projection.CompanyCode = _CompanyCode.CompanyCode

" In the select list, use path expressions:
  _CompanyCode-CompanyName as CompanyText,

Module 4: RAP (RESTful ABAP Programming) CORE

The 3 Pillars of RAP

  • Data Model: CDS View Entities (Interface & Consumption views).
  • Business Logic: Behavior Definition (BDEF) & Behavior Implementation (BIL).
  • Service Exposure: Service Binding (OData V2/V4).

Behavior Definition (BDEF) Syntax

define behavior for ZI_BillingDoc
  implementation in class zbp_i_billingdoc unique
  persistent table zbillingdoc
  draft enabled
{
  " CRUD Operations
  create;
  update;
  delete;

  " Field Properties
  field ( readonly ) BillingDocument;
  field ( mandatory ) CustomerName;

  " Validations & Determinations
  validation validateCustomer on save { create; update; }
  determination setDefaults on modify { create; }
}

EML (Entity Manipulation Language)

How to read or modify RAP entities from within ABAP code (e.g., in a behavior implementation or a separate class).

" READ
READ ENTITIES OF zsb_billingdoc
  ENTITY ZI_BillingDoc
  ALL FIELDS WITH VALUE #( ( BillingDocument = '0001' ) )
  RESULT DATA(lt_result).

" MODIFY
MODIFY ENTITIES OF zsb_billingdoc
  ENTITY ZI_BillingDoc
  SET FIELDS WITH VALUE #( ( BillingDocument = '0001'
                             CustomerName = 'New Name' ) )
  REPORTED DATA(DATA(lt_reported)).

" COMMIT
COMMIT ENTITIES.

Module 5: Joule & AI-Augmented Dev NEW

What is Joule?

Joule is SAP's generative AI assistant. In the C_ABAPD exam, you will be tested on your ability to use Joule to accelerate development, not replace your understanding of the code.

Top Joule Use Cases for the Exam

  • Generate RAP Boilerplate: "Create a RAP business service for entity ZI_MyEntity."
  • Explain Code: Highlight code and ask, "Explain this ABAP code."
  • Optimize SQL: "Optimize this CDS view for better performance."
  • Generate Test Data: "Create an ABAP OO class to generate test data for ZI_MyEntity."

💡 Exam Tip: Prompt Engineering

Be specific. Instead of "Write ABAP code", use:

"Write an ABAP class that implements IF_OO_ADT_CLASSRUN. It should read data from CDS view ZI_MyView using EML and output the result using out->write()."

📋 Boilerplate Code (Copy-Paste Ready)

📖 EML: READ ENTITIES

" Read specific fields for specific keys
READ ENTITIES OF ZI_MyEntity IN LOCAL MODE
  ENTITY ZI_MyEntity
    FIELDS ( Description Amount )
    WITH VALUE #( ( MyKeyField = '12345' ) )
  RESULT DATA(lt_result)
  FAILED DATA(lt_failed)
  REPORTED DATA(lt_reported).

" Read ALL fields for ALL instances
READ ENTITIES OF ZI_MyEntity IN LOCAL MODE
  ENTITY ZI_MyEntity
    ALL FIELDS
  RESULT DATA(lt_all_result).

✏️ EML: MODIFY ENTITIES & COMMIT

MODIFY ENTITIES OF ZI_MyEntity IN LOCAL MODE
  ENTITY ZI_MyEntity
    UPDATE FIELDS ( Description )
    WITH VALUE #( ( MyKeyField = '12345' Description = 'New Text' ) )
  REPORTED DATA(lt_reported)
  FAILED DATA(lt_failed).

" ALWAYS commit after modify in standalone classes
COMMIT ENTITIES
  RESPONSE OF ZI_MyEntity
  FAILED DATA(lt_commit_failed)
  REPORTED DATA(lt_commit_reported).

⚙️ Managed Behavior Definition (with Draft)

define behavior for ZI_MyEntity
  implementation in class zbp_i_myentity unique
  persistent table zmy_table
  draft enabled
{
  create;
  update;
  delete;

  field ( readonly ) MyKeyField;
  field ( mandatory ) Description;

  determination setDefaults on modify { create; }
  validation validateData on save { create; update; }
}
