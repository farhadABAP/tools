🎯 Practical Implementation Scenarios

Real-world patterns: These scenarios mirror what you'll encounter in actual ABAP Cloud development projects and practical assessments.

Scenario 1: Expose Standard SAP Data as Fiori-Ready API

Business Requirement: Create a custom CDS view based on I_BusinessPartner to expose customer data for a Fiori app.

  • Create CDS view ZI_Customer_### with annotations for search and UI.
  • Expose fields: BusinessPartner, BusinessPartnerFullName, CreationDate.
  • Make BusinessPartnerFullName searchable.
  • Add @UI.lineItem annotations for list report display.
🔍 Implementation Checklist:
  • Use @Search.defaultSearchElement: true on the searchable field
  • Set @AccessControl.authorizationCheck: #CHECK (requires DCL)
  • Activate the view before testing
  • Verify the view appears in the ABAP Dictionary

Scenario 2: Build Managed RAP Service with Business Logic

Business Requirement: Create a RAP service for managing custom business objects with automatic field population.

  • Create Behavior Definition for ZI_Customer_###.
  • Enable create and update operations (disable delete).
  • Make BusinessPartner read-only.
  • Implement determination to auto-populate CreationDate on create.
🔍 Implementation Checklist:
  • Use field ( readonly ) BusinessPartner; in BDEF
  • Map determination to on modify { create; }
  • Generate and activate Behavior Implementation class
  • Test with "Preview" in the Service Binding

Scenario 3: Test RAP Service with EML

Business Requirement: Create an executable class to test the RAP service by creating and reading records.

  • Create class ZCL_Test_### implementing IF_OO_ADT_CLASSRUN.
  • Use EML to create a new customer record.
  • Commit the transaction.
  • Read and display the created record.
🔍 Implementation Checklist:
  • Use IN LOCAL MODE in all EML statements
  • Provide %cid in CREATE operations
  • Check FAILED and REPORTED tables for errors
  • Use COMMIT ENTITIES to persist changes
  • Output results using out->write()

Scenario 4: Implement Access Control (DCL)

Business Requirement: Restrict data access so users only see records they created or records with status 'ACTIVE'.

  • Create a DCL artifact for the CDS view.
  • Define WHERE clause based on CreatedBy and Status.
  • Test with different user contexts.
🔍 Implementation Checklist:
  • Use $user system variable for current user
  • Link DCL to the correct CDS view entity
  • Activate both CDS view and DCL together

⚠️ Common Implementation Pitfalls

Production lessons learned: These are the most common mistakes that cause runtime errors or failed activations in ABAP Cloud.

🚨 Pitfall 1: Missing "IN LOCAL MODE" in EML

When writing EML in a standalone ABAP class (outside RAP context), you must use IN LOCAL MODE. Without it, the system tries to apply feature controls that don't exist in your test context.

" ❌ WRONG - Will fail or dump
MODIFY ENTITIES OF ZI_MyEntity
  ENTITY ZI_MyEntity
  CREATE FIELDS ( Description )
  WITH VALUE #( ( Description = 'Test' ) ).

" ✅ CORRECT
MODIFY ENTITIES OF ZI_MyEntity IN LOCAL MODE
  ENTITY ZI_MyEntity
  CREATE FIELDS ( Description )
  WITH VALUE #( ( %cid = 'c1' Description = 'Test' ) ).

🚨 Pitfall 2: Activation Cascade Failures

In RAP, artifacts have dependencies. If you modify a CDS view, the Behavior Definition may become inactive. If the BDEF is inactive, the Service Binding breaks.

Solution: Always use "Activate All" (Ctrl+Shift+F3 in ADT) after making changes. Check the activation log for errors.

🚨 Pitfall 3: Missing %cid in EML CREATE

When creating records via EML, you must provide a temporary control ID (%cid). The RAP framework uses this to track the record before it gets a real database key.

" ✅ CORRECT - Always provide %cid
MODIFY ENTITIES OF ZI_MyEntity IN LOCAL MODE
  ENTITY ZI_MyEntity
  CREATE FIELDS ( Description )
  WITH VALUE #( ( %cid = 'cid1' Description = 'Test' ) )
  MAPPED DATA(lt_mapped).

🚨 Pitfall 4: Using #CHECK Without DCL

If you set @AccessControl.authorizationCheck: #CHECK on a CDS view, you MUST create a corresponding DCL (Data Control Language) artifact. Otherwise, the view returns empty data.

Solution: Either create a DCL artifact or use #NOT_ALLOWED if access control is not needed.

🚨 Pitfall 5: Forgetting to Check FAILED/REPORTED Tables

After EML operations, always check the FAILED and REPORTED tables. If you don't, your code will silently fail and you won't know why.

MODIFY ENTITIES OF ZI_MyEntity IN LOCAL MODE
  ENTITY ZI_MyEntity
  CREATE FIELDS ( Description )
  WITH VALUE #( ( %cid = 'c1' Description = 'Test' ) )
  FAILED DATA(lt_failed)
  REPORTED DATA(lt_reported).

" ✅ Always check for errors
IF lt_failed IS NOT INITIAL.
  out->write( 'Operation failed:' ).
  out->write( lt_reported ).
  RETURN.
ENDIF.

⚡ EML Code Patterns

📖 EML READ with Error Handling

READ ENTITIES OF ZI_MyEntity IN LOCAL MODE
  ENTITY ZI_MyEntity
  ALL FIELDS WITH VALUE #( ( MyKey = '123' ) )
  RESULT DATA(lt_result)
  FAILED DATA(lt_failed)
  REPORTED DATA(lt_reported).

IF lt_failed IS NOT INITIAL.
  out->write( 'Read failed:' ).
  out->write( lt_reported ).
  RETURN.
ENDIF.

out->write( lt_result ).

✏️ EML CREATE with Commit

MODIFY ENTITIES OF ZI_MyEntity IN LOCAL MODE
  ENTITY ZI_MyEntity
  CREATE FIELDS ( Description Amount )
  WITH VALUE #( ( %cid = 'cid1' Description = 'Test' Amount = 100 ) )
  MAPPED DATA(lt_mapped)
  FAILED DATA(lt_failed)
  REPORTED DATA(lt_reported).

IF lt_failed IS NOT INITIAL.
  out->write( 'Creation failed:' ).
  out->write( lt_reported ).
  RETURN.
ENDIF.

COMMIT ENTITIES
  RESPONSE OF ZI_MyEntity
  FAILED DATA(lt_commit_failed)
  REPORTED DATA(lt_commit_reported).

out->write( 'Created:' ).
out->write( lt_mapped-myentity[ 1 ]-MyKey ).

🔄 EML UPDATE

MODIFY ENTITIES OF ZI_MyEntity IN LOCAL MODE
  ENTITY ZI_MyEntity
  UPDATE FIELDS ( Description )
  WITH VALUE #( ( MyKey = '123' Description = 'Updated' ) )
  FAILED DATA(lt_failed)
  REPORTED DATA(lt_reported).

IF lt_failed IS NOT INITIAL.
  out->write( 'Update failed:' ).
  out->write( lt_reported ).
  RETURN.
ENDIF.

COMMIT ENTITIES.

🗄️ CDS View Patterns

📄 CDS View with Fiori Annotations

@AccessControl.authorizationCheck: #CHECK
@EndUserText.label: 'Custom Entity'
@Search.searchable: true
define root view entity ZI_MyEntity
  as select from I_ReleasedTable
{
      @UI.hidden: true
  key ID,

      @Search.defaultSearchElement: true
      @UI.lineItem: [{ position: 10, label: 'Name' }]
      Name,

      @UI.lineItem: [{ position: 20, label: 'Status' }]
      Status
}

🛡️ Data Control Language (DCL)

@EndUserText.label: 'Access Control'
define role ZI_MyEntity_Role {
  grant
    select on
      ZI_MyEntity
        where
          ( Status = 'ACTIVE' ) or
          ( CreatedBy = $user );
}

🔗 CDS Association with Path Expression

define view entity ZI_MyEntity
  as select from I_BaseView
  association [0..1] to I_CompanyCode as _CompanyCode 
    on $projection.CompanyCode = _CompanyCode.CompanyCode
{
  key ID,
  CompanyCode,
  
  " Path expression
  _CompanyCode.CompanyName as CompanyNameText
}

🧱 RAP Behavior Patterns

⚙️ Managed BDEF with Determination & Validation

managed implementation in class zbp_i_myentity unique;
strict ( 2 );

define behavior for ZI_MyEntity alias Entity
persistent table zmy_db_table
draft enabled
{
  create;
  update;
  delete;

  field ( readonly ) ID;
  field ( mandatory ) Name;

  " Determination runs automatically
  determination setDefaultStatus on modify { create; }
  
  " Validation runs on save
  validation checkName on save { create; update; }
}

🚀 Executable Class (IF_OO_ADT_CLASSRUN)

CLASS zcl_test DEFINITION PUBLIC FINAL CREATE PUBLIC.
  PUBLIC SECTION.
    INTERFACES if_oo_adt_classrun.
ENDCLASS.

CLASS zcl_test IMPLEMENTATION.
  METHOD if_oo_adt_classrun~main.
    DATA(lv_text) = |Hello ABAP Cloud|.
    out->write( lv_text ).
    
    " Call EML operations here
  ENDMETHOD.
ENDCLASS.

🤖 AI Prompt Patterns

Accelerate development: Use these prompts with SAP's Joule AI assistant to generate boilerplate code quickly.

Prompt: Generate RAP BDEF

Create a managed RAP behavior definition for the CDS view entity ZI_MyEntity. Make it draft enabled. Allow create, update, and delete. Make the field 'ID' readonly. Add a determination named 'setDefaultStatus' that triggers on modify for create.

Prompt: Generate EML Test Class

Write an executable ABAP class implementing IF_OO_ADT_CLASSRUN. In the main method, use EML IN LOCAL MODE to create a new record in ZI_MyEntity with the Name 'Test'. Commit the entities and output the mapped key or any reported errors to the console.

Prompt: Generate CDS View

Create a CDS view entity named ZI_MyEntity based on I_BusinessPartner. Expose BusinessPartner, BusinessPartnerFullName, and CreationDate. Add @UI.lineItem annotations for all fields and make BusinessPartnerFullName searchable.
